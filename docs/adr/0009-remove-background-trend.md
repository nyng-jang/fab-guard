# 0009. 원본의 시간 추세: 걷어낸 버전과 남긴 버전을 둘 다 만듦

- 상태: 확정 (2026-11-10 나영 선택: 둘 다 만들기)
- 날짜: 2026-11-10

## 맥락
기준선 탐지기로 첫 더미데이터를 점검하자, 이상을 심지 않은 뒤쪽 로트 9개 중 5개가 로트 단위 이상으로 잡혔습니다. 원인을 보니 원본 자체에 50일 동안 여러 센서가 함께 서서히 움직이는 추세가 들어 있었습니다.

| 센서 | 로트 평균과 날짜의 상관 | 50일간 변화(웨이퍼 σ) |
|---|---|---|
| focus_offset | +0.88 | +2.0 |
| thickness_uniformity | +0.91 | +1.7 |
| defect_count / density | +0.90 | +1.7 |
| etch_rate | +0.74 | +1.6 |
| deposition_rate | -0.86 | -1.5 |
| temperature | +0.74 | +1.2 |
| pressure | +0.71 | +0.9 |
| leakage_current | +0.65 | +0.7 |

이 추세는 모든 장비에 걸쳐 있고 yield와는 상관이 없습니다. 이전 분석에서 "따로 심어진 이상은 없어 보인다"고 했던 것은 웨이퍼 단위 3σ 점검만 했기 때문이고, 로트 단위로 보면 추세가 보입니다.

## 결정
두 버전을 모두 만들어 보관합니다.
- `data/injected/` (기본, 1차 검증용): 추세를 걷어낸 버전
- `data/injected_keep_trend/` (2차 검증용): 추세를 남긴 버전. 심은 이상과 정답지는 같음

기본 설정은 위 9개 센서의 추세를 선형으로 걷어낸 뒤(leakage_current는 로그 척도) 이상을 심습니다. 전체 평균은 그대로 둡니다. 걷어낸 기울기는 data/injected/background_trend_removed.csv 에 남깁니다. `--background keep` 으로 추세를 남긴 변형도 만들 수 있습니다.

## 이유
첫 검증에서 추세를 남기면 "앞 25로트 = 평소"라는 전제가 깨져, 심지 않은 로트가 이상으로 잡히고 심은 드리프트(E1)와 원래 추세가 섞여 채점이 모호해집니다. 첫 검증은 정답이 깔끔해야 합니다. 반면 추세가 남은 버전은 실데이터(SECOM)처럼 기준이 천천히 변하는 환경을 미리 시험할 수 있어, 합성에서 실데이터로 가는 중간 단계로 씁니다.

## 검토한 대안
- 한쪽만 만들기: 걷어낸 버전만 있으면 현실성 시험을 못 하고, 남긴 버전만 있으면 첫 채점이 모호해짐
- 추세를 하나의 이상(E0)으로 라벨링: 모든 장비가 같이 움직여 원인 장비가 없고, 50로트 전체가 이상이 되어 기준 구간이 사라짐

## 결과
- 추세를 걷어낸 뒤 점검 결과: 뒤쪽 깨끗한 로트 9개 중 로트 오탐 2개(LOT_0034 pressure z=-3.6, LOT_0040 leakage_current z=+4.4), 앞 25로트는 0개.
- 깨끗한 웨이퍼의 원본 값은 추세 보정만큼 바뀝니다. 원본과 같은 값이 필요하면 `--background keep` 을 씁니다.
- 추세를 남긴 버전의 점검 결과(reports/validation_report_keep_trend.md): 뒤쪽 깨끗한 로트 로트 오탐 5/9. 고정 기준 탐지기의 한계가 그대로 드러남.
- 탐지기를 만든 뒤 `keep` 버전에서도 돌려 보고, 실제 SECOM처럼 기준이 천천히 변하는 데이터에 대비한 이동 기준이 필요한지 판단합니다.
