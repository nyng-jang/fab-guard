# 0001. 합성 데이터로 검증한 뒤 SECOM에 적용

- 상태: 확정
- 날짜: 2026-11-10

## 맥락
실제 공장 데이터에는 접근할 수 없습니다. 탐지와 원인 분석이 맞는지 확인하려면 정답이 있는 데이터가 필요하고, 포트폴리오로서는 "실제 데이터에서도 통한다"를 보여줘야 합니다.

## 결정
1. 합성 데이터(archive.zip, 웨이퍼 1,250장)에 이상을 심어 정답을 아는 상태에서 에이전트 로직을 검증합니다.
2. 같은 로직을 UCI SECOM(웨이퍼 1,567건, 센서 590개, 불량 104건)에 적용합니다.
3. 합성에서 실데이터로 옮기며 무엇이 깨졌고 어떻게 고쳤는지를 정리합니다.

## 이유
합성 데이터는 장비 ID와 센서 이름이 있어 원인 후보까지 채점할 수 있고, SECOM은 결측이 많고 불량이 드문 실제 환경을 보여 줍니다. 둘을 순서대로 쓰면 "정답을 아는 검증"과 "현실 적용"을 모두 얻습니다.

## 검토한 대안
- SECOM만 사용: 센서가 익명이고 장비 정보가 없어 원인 분석을 채점할 수 없음
- 합성 데이터만 사용: 실제 데이터에서 통하는지 보여줄 수 없음

## 결과
- SECOM에서는 원인 후보를 "센서 번호 + 변화 양상"까지만 설명할 수 있습니다. 이 한계를 문서에 솔직하게 적습니다.
- SECOM 라벨은 웨이퍼 합격/불합격이라 공정 이상과 완전히 같지 않습니다. 탐지 결과가 불량과 얼마나 겹치는지로 평가합니다.
