# 0015. 리포트는 개조식 정식 보고서 양식으로 씀

- 상태: 확정
- 날짜: 2026-11-18

## 맥락
목업의 첫 리포트 초안은 해요체 대화문에 구성이 단순해서, 공식 기록으로 쓰기 어렵다는 피드백(나영)을 받았습니다.

## 결정
리포트(이상 발생 보고서)는 해요체를 쓰지 않고 개조식(~함, ~됨)으로 쓰며, 아래 구성을 따릅니다.

| 순서 | 항목 | 내용 |
|---|---|---|
| 머리 | 문서번호·상태 | `RPT-YYYYMMDD-E번호`, 초안(AI 작성) / 승인 완료 |
| 머리 | 메타 표 | 발생 일자, 등급(임시 기준 표시), 대상 로트·웨이퍼 수, 기술 노드·제품, 장비 4종 |
| 1 | 개요 | 2~3문장 요약 |
| 2 | 감지 기준 | 기준 구간, 관리 한계(평균 ± 3σ), 이관 규칙 |
| 3 | 데이터 분석 | 항목별 기준 평균, 관리 범위, 발생 평균, 편차(σ), 판정(이탈 n/N매, 경계, 정상, 미수신) 표와 관리도 |
| 4 | 영향 평가 | 대상 웨이퍼 수율과 기준 대비 차이(%p), 영향 범위 |
| 5 | 원인 분석 | AI 원인 후보, 추정 가능성, 근거. "판단 보조 자료"임을 명시 |
| 6 | 조치 사항 | AI 권고 조치 + 담당자가 쓰는 실시 조치, 재발 방지 대책 |
| 7 | 판정 및 승인 | 원인 판정(일치 / 불일치 / 미확정), 승인자, 승인 일시 |

- 숫자(평균, σ, 이탈 매수, 수율)는 코드가 계산하고 AI는 문장만 씁니다(ADR 0004).
- 원인 판정을 고르기 전에는 승인할 수 없게 해서 피드백이 빠지지 않게 합니다.

## 이유
리포트는 공식 기록이라 다시 찾아 비교하기 쉬워야 하고(같은 양식), 숫자와 판단 근거가 한눈에 보여야 합니다.

## 검토한 대안
- 자유 서술 초안: 사람마다 형식이 달라져 과거 사례 검색·비교가 어려움

## 결과
- 분석글 프롬프트와 정적 결과 페이지는 이 문체·구성을 따릅니다. 화면 안내 문구(버튼, 도움말)의 톤은 따로 정합니다.
- 수율은 기술 노드별 수준 차이가 있어, 실제 구현에서는 노드별 기준과 비교합니다(ADR 0008).
